## 1. 주요 작업

| 작업 | 실행 결과 |
| --- | --- |
| 수정(연필) | 서버 주소와 Sync 자격 증명을 입력하는 대화상자를 엽니다 |
| 적용 / 연결 | Wizard에서 Sync 서비스에 로그인합니다 |
| 연결 해제 | Wizard의 연결을 해제합니다 |
| 열기 | 컴퓨터의 구성 파일을 Wizard로 불러옵니다 |
| 백업 | 구성을 JSON으로, 또는 JSON, 생성된 환경 파일, `recovery.json`, `RECOVERY.md`가 포함된 ZIP으로 다운로드합니다 |
| 가져오기 | 저장된 인스턴스 설정을 가져옵니다. 구성이 없으면 현재 버전에서 제안임을 표시한 설정을 불러옵니다 |
| 보내기 | Wizard 구성을 전송하고 인스턴스를 자동으로 다시 시작합니다 |
| 다시 시작 | 전송된 구성으로 서비스를 다시 시작합니다 |
| 등록 / 등록 해제 | 구성된 Runner 관리자를 확인/등록하거나 등록 해제합니다 |
| Harvest | GitLab 데이터, 인증서, 인증서 갱신 상태의 콜드 스냅샷을 Seed 디렉터리에 게시합니다 |
| Harvest 및 설정 백업 | 기본 Harvest와 이에 일치하는 구성 ZIP을 함께 조정하여, ZIP을 다운로드하고 별도로 보관할 수 있게 합니다 |
| 개발 미리보기 설정 | 운영 환경을 보존하면서 선택적 Review 및 Beta에 필요한 정식 소스/빌드 연결을 명시적으로 준비합니다 |
| 인증 정보 만료 | 선택된 자동화 자격 증명의 메타데이터를 읽고 알려진 날짜, 경고, 알 수 없는 상태를 표시합니다 |
| 시스템 진단 | 구성된 Registry의 연결을 확인합니다. 별도의 선택적 작업으로 선택한 Runner 데몬을 통해 정확한 도우미 이미지를 가져옵니다 |
| Seed | 완료된 Seed를 검증하고 새로운 라이브 서비스 데이터 디렉터리에 복원합니다 |
| 초기화 | 초기화 절차를 통해 기본 구성과 프로젝트 구성을 삭제합니다 |
| 업데이트 | 기존 업데이트 절차를 통해 소스 코드를 업데이트합니다 |

사전 조건과 제한 사항은 [개발 미리 보기](DEVELOPMENT_PREVIEWS.md),
[조정된 백업](COORDINATED_BACKUP.md), [자격 증명 만료](TOKEN_EXPIRY.md),
[시스템 진단](SYSTEM_DIAGNOSTICS.md)을 참조하세요.

**구성과 영구 서비스 데이터는 별도로 관리됩니다.** 열기/백업과 보내기/가져오기는
구성을 관리합니다. Harvest/Seed는 서비스 데이터를 처리합니다. 어느 구성 다운로드에도
Seed, 데이터베이스, Registry 내용은 포함되지 않습니다. 가져오기로 구성을 확인할 때는
Harvest와 Seed가 필요하지 않습니다.

새 구성 ZIP에는 `recovery.json`과 `RECOVERY.md`가 포함됩니다. 이 파일들은 확인 가능한
저장된 릴리스/소스/이미지 식별 정보와 관찰된 식별 정보를 기록하고 정보의 완전성을 설명합니다.
내보낸 참조만으로 이미지가 보존되지는 않습니다. 복구에 의존하기 전에 접근 가능한 이미지,
그에 일치하는 비공개 구성, 별도로 완료된 Seed를 보관하세요. 이전 구성 백업도 계속 열 수 있지만,
복구 메타데이터가 없으면 검증된 복구 세트라고 할 수 없습니다. 확장 ZIP에는 호환되고 승인된
1.0.0+ 복구 도구가 필요합니다. 이 요구 사항이 저장된 런타임 이미지를 업그레이드하지는 않습니다.
[복구 입력 안내](RECOVERY_CONTRACT.md)에 따라 모든 입력이 서로 일치하는지 검증하세요.

현재 구현 세부 사항: 기존 Wizard의 **Seed** 작업은 데이터를 복원하기 전에 폼의 기본 구성도
전송합니다. 실행 전에 폼을 확인하세요. 최초 시작 제안 기능은 이 결합 관계를 변경하지 않았습니다.
0장의 초기 설정에서는 보내기를 사용하세요.

Harvest는 GitLab을 중지하며, 데이터를 복사하기 전에 정상 종료를 요구합니다. 인증서 갱신과
조정하고, 복사가 성공한 뒤에만 체크섬이 포함된 완료 매니페스트를 게시합니다. 이전에 완료된
스냅샷은 계속 사용할 수 있습니다. Seed는 스냅샷을 검증하고, 복원 전에 일치하는 GitLab 이미지를
요구합니다. 일치하는 구성 백업을 별도로 저장하고 [복구 계약](RECOVERY_CONTRACT.md)을 따르세요.
로컬 라이브 레이아웃에는 별도의 외부 Seed 파일시스템이 필요합니다. 레거시 볼륨 레이아웃에서는
분리된 Seed를 유지되는 라이브 볼륨에 둘 수 있지만, 이 방식은 해당 볼륨의 손실에 대비하지 못합니다.
