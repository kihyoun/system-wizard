# 고정된 소스에서 Wizard 저장소 초기화

이 절차는 레거시 관리형 소스 절차입니다. 명시적으로 채택한
[소스 우선 저장소](../project-bootstrap/wizard-source-primary/README.md)는 자체 병합 요청으로
직접 개발하며 소스를 가져오지 않습니다. 이러한 저장소에 커밋된 일반
`.system-bootstrapper/build-v1/` 생성기는 레거시 소스 스냅샷에서 제외됩니다. 관리형 빌드
활성화는 이 예약된 네임스페이스에 자체 검토된 레시피를 설치합니다.

등록된 Wizard 프로젝트는 기존 인터페이스를 나타냅니다. 소스 초기화는 별도의 명시적
작업입니다. 자동 등록, 시작, 가져오기, 구성 보내기는 애플리케이션 소스를 가져오지 않습니다.

## 작업 사용하기

1. 서로 일치하는 System과 Wizard 버전을 실행하고 기본 Wizard 등록을 완료한 다음,
   Sync에 연결하고 프로젝트 목록을 가져오세요.
2. 관리형 Wizard 프로젝트를 펼치고 **Wizard 소스 초기화**를 선택하세요.
3. 미리 보기에서 저장소, 소스 리비전, 파일 수를 확인하세요.
4. **소스 가져오기**를 선택하세요. 인증된 비동기 작업이 완료 또는 해결 방법이 있는 충돌을
   보고합니다. 요청이 중단된 경우 대화상자를 닫고 다시 열어 재시도할 수 있습니다.

이 인스턴스의 등록으로 생성된 비공개 저장소만 허용됩니다. 소유권 마커, 식별 정보, 기본 브랜치,
비활성화된 관리형 CI가 일치해야 합니다. 새 소스 경로와 출처 마커는 `[skip ci]`와 함께 원자적으로
커밋됩니다. 기존 경로는 절대로 덮어쓰지 않습니다. 재시도는 내용, 실행 권한 모드, 가져오기 커밋
증거가 일치하는지 검증한 뒤 성공을 보고합니다. 관리자의 편집이 있으면 파괴적인 초기화 대신
검사가 필요합니다.

스캐폴드 README는 변경하지 않습니다. 원본 소스 README는
`.system-bootstrapper/SOURCE_README.md`에 배치합니다. 원래 업스트림 `.gitlab-ci.yml`은
바이트 그대로 보존하지만, GitLab의 CI 경로는 계속 비활성화된 `.system-bootstrapper/ci.yml`을
가리킵니다. 파이프라인은 시작하지 않습니다. 안전한 것으로 알려진 `SKIP_PREFLIGHT_CHECK=true`
값은 `.system-bootstrapper/preflight.env`에 별도로 제공하며, 로컬 dotenv 파일은 제외합니다.

실행 중인 인터페이스, 라우팅, 운영 환경 URL은 그대로 유지합니다. Beta와 Review는 계속
비활성화됩니다. 소스 초기화는 빌드나 배포를 시작하지 않습니다.
[관리형 빌드 활성화](WIZARD_BUILD.md)는 별도의 명시적 작업입니다. Review/Beta 배포와
[운영 환경 승격](../project-bootstrap/wizard-production/README.md)도 별도의 명시적 작업입니다.
소스를 가져오는 것은 이미지를 승격하지 않습니다.

## 불변 소스 패키지 빌드

System 이미지를 빌드하기 전에 고정된 Wizard 서브모듈을 초기화하세요.

```sh
git submodule update --init wizard
bash project-bootstrap/wizard-source/prepare.sh
```

일반적인 루트 `start.sh`는 Compose가 System 이미지를 빌드하기 전에 준비를 호출합니다.
수동으로 System 이미지를 빌드할 때도 먼저 같은 명령을 실행해야 합니다. 이미지 빌드는 생성된
매니페스트와 파일 해시를 검증하며, 준비를 생략하면 실패합니다. 생성된 `snapshot.json`은
커밋하지 마세요.

준비는 System의 HEAD에 커밋된 Wizard gitlink의 Git 객체를 읽습니다. 수정된 체크아웃 파일,
추적되지 않는 파일, 다르게 체크아웃된 Wizard 브랜치는 스냅샷을 변경할 수 없습니다. 바이너리
바이트와 실행 권한 모드를 보존하고 심볼릭 링크와 중첩 서브모듈을 거부하며, dotenv 파일,
자격 증명 파일 규칙에 해당하는 파일, Seed, 의존성 디렉터리, 빌드 출력을 제외합니다. 커밋된
애플리케이션 소스는 평소처럼 검토하세요. 파일 이름 필터링은 임의의 소스 코드에 대한 비밀 정보
스캐너가 아닙니다.

호스트의 Node는 선택 사항입니다. 없으면 준비 단계에서 검토된 `bootstrapper` 런타임
레시피를 `system-bootstrapper-source-tools:local`로 빌드한 뒤, 네트워크를 비활성화하고
소스/Git 객체 마운트를 읽기 전용으로 설정하여 Node/Git 도구를 실행합니다. 연결된 Git
작업 트리에서는 참조하는 메타데이터 디렉터리에 계속 접근할 수 있어야 합니다. 패키징 컨테이너에는
Docker 소켓을 마운트하지 않습니다.

## 상태와 복구

기존 비공개 Wizard 프로젝트 구성에는 버전이 지정된 `wizardWorkflow` 기록이 들어 있습니다.
작업, 소스 리비전, 매니페스트 해시, 단계, 가져오기 커밋, 안전한 실패 메시지를 기록합니다.
등록 및 저장소 식별 정보는 보존됩니다. 기존 서버 소유 프로젝트 보존 기능은 보내기와 다시 시작을
거쳐 전체 기록을 유지합니다. 응답이 유실된 후 재시도하면 또 다른 가져오기 커밋을 만드는 대신
저장소를 검사합니다. 예약된 가져오기 이후 소스 리비전을 업그레이드하려면 별도의 검토된 작업이
필요합니다.

소스 스냅샷이 없으면 준비한 뒤 일치하는 System 이미지를 다시 빌드하세요. 소유권, 경로,
CI 충돌이 있으면 먼저 저장소와 로컬 등록을 검사하세요. 초기화를 통과시키기 위해 저장소를
삭제/재생성하거나 자격 증명을 초기화하지 마세요.

## 격리된 검증

Sync를 컴파일하고 스냅샷을 생성한 뒤 다음을 실행하세요.

```sh
node tests/wizard/source-package.js
node tests/wizard/source-workflow.js
ruby tests/wizard/source-import.rb
```

패키지 테스트는 폐기 가능한 Git 저장소를 만듭니다. 워크플로 테스트는 임시 비공개 구성과
스텁 Rails 전송을 사용합니다. Ruby 어댑터 테스트는 메모리 내 GitLab API 픽스처를 사용합니다.
이 테스트들은 실행 중인 GitLab에 접속하거나 플랫폼을 변경하지 않습니다. `wizard/package.json`에
선언된 Node/npm 버전으로 Wizard 검사를 실행하세요. `npm ci`, `npm run lint`, `npm test`,
`npm run build`, `npm run test:config-export`를 사용합니다. 관리형 빌드 레시피는 일치하는
소스 도구 체인 프로필을 선택합니다. 과거 예약은 정확한 레시피 해시를 유지합니다.
