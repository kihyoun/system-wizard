# 배포 후 기본 안내형 미리 보기 승인 검사

공유 `guided-preview.js` 어댑터는 네이티브 Wizard 설정, 소스 우선 채택,
GitLab 파이프라인 및 환경 도우미를 통해 초기 안내형 설정을 검사합니다.
전체 일회용 플랫폼 게이트는 자체 소유 후보에서 Review와 Beta를 활성화한 상태로 실행합니다.
후속 버전을 게시하려면 완료된 단계와 네이티브 파이프라인, 병합, 환경 및
운영 환경이 변경되지 않았다는 증거가 필요합니다.

선택적 `guided-preview-live.js` 진입점으로도 명시적으로 선택한 로컬 실행 컨트롤러에서
이 어댑터를 실행할 수 있습니다. 비공개 입력은 운영자 인스턴스 하나를 식별하며,
기본 호스트가 없고 컨트롤러를 설치하거나 운영 환경을 승격하지 않습니다.
이 선택적 운영자 검사는 일반 릴리스에 필수가 아니며 필수 일회용 플랫폼 게이트를 대체할 수 없습니다.
오프라인 전송 계약은 어댑터 동작을 입증하지만 실제 실행을 증명하지는 않습니다.
성공한 검사 전용 보고서는 계획이며, 기능 승인 통과가 아닙니다.

## 사전 조건

정확히 보존된 컨트롤러/Wizard 이미지 쌍이 있는 새로운 초기 관리형 Wizard 등록을 사용하세요.
선택한 설치의 공개 릴리스 설치 기록 또는 네이티브 소스 설치 출처 기록을 보존하세요.
소스 출처 기록은 이미지/소스 식별 정보를 입증하며, 승인 검사 통과나 공개 릴리스 상태를 뜻하지 않습니다.
일반 구성, 관리형 Wizard 등록, GitLab HTTPS, 레지스트리 접근, Runner 등록 및
신뢰할 수 있는 정확한 호스트 DNS/인증서가 이미 작동해야 합니다.
승인된 불변 System 환경 도우미가 네이티브 절차로 프로비저닝되어 있어야 합니다.
선택한 Runner는 `docker`와 `wizard-source-primary` 태그를 포함하여 일반 네이티브 Wizard 작업을 허용해야 합니다.
해당 작업에서 패키지, 브라우저 및 이미지 의존성을 사용할 수 있어야 합니다.

네임스페이스와 아직 존재하지 않는 새 비공개 소스 프로젝트 이름을 선택하세요. 공개 HTTPS
Wizard 소스 또는 포크에는 승인된 컨트롤러 스냅샷과 동일하게 승인된 기본 CI 생성기 바이트가
있어야 합니다. 소스 전송은 공개 DNS를 검증하고 Git의 이름 해석을 고정합니다. 비공개 소스
엔드포인트, 조작된 기록, 편집된 CI 생성기는 승인 검사를 단축하는 방법이 아닙니다. Review
호스트는 사용 중이지 않아야 하고, 선언된 인증서/키가 있어야 하며, 이 설치로 해석되어야 합니다.
Beta는 비활성화된 상태로 둘 수 있습니다. 독립적인 System 소스 설정은 별도로 완료하세요.
이 수명 주기에는 또 다른 System 마이그레이션 파이프라인이 필요하지 않습니다.

도구는 Node 24와 로컬 Unix 소켓에 대한 Docker 접근 권한을 갖춘 운영자의 Linux 호스트에서
실행됩니다. 기본 인증을 읽기 전에 운영자가 제공한 정확한 컨트롤러 이미지 ID를 확인합니다.
이 ID는 독립적으로 검토된 배포/이미지 증거에서 얻으세요. 검사를 통과시키려고 임의의 현재
이미지로 대체하지 마세요.

## 비공개 입력과 명령

입력과 보고서를 체크아웃 밖에 보관하세요. 비공개 운영자 디렉터리와 다음 형태의 0600 권한
JSON 입력을 만들고, 모든 예시 값을 바꾸세요.

```json
{
  "version": 1,
  "syncUrl": "https://sync.example.com",
  "gitlabUrl": "https://gitlab.example.com",
  "controllerImageId": "sha256:<64 verified hexadecimal characters>",
  "settings": {
    "version": 1,
    "namespace": "operator-team",
    "wizard": {
      "mode": "import",
      "project": "wizard-preview-source",
      "origin": "https://github.com/REPLACE_OWNER/REPLACE_REPOSITORY.git"
    },
    "review": {
      "enabled": true,
      "host": "review.example.com",
      "ssl": "/ssl/live/review.example.com/fullchain.pem",
      "sslKey": "/ssl/live/review.example.com/privkey.pem"
    },
    "beta": {"enabled": false, "host": "", "ssl": "", "sslKey": ""}
  },
  "reportPath": "/root/private-preview-acceptance/report.json",
  "timeBudgetMilliseconds": 3600000
}
```

먼저 기본 사전 조건 계획을 검토하세요.

```sh
node tests/e2e/guided-preview-live.js --check-only /root/private-preview-acceptance/input.json
```

검사 전용 실행은 보존된 설치 이미지 쌍, 운영 환경 식별 정보, 기본 DNS/인증서/소스/Runner
사전 검사를 검증합니다. 저장소를 가져오거나, 소스 파이프라인을 시작하거나, 연결을 채택하거나,
Review를 배포하지 않습니다. 기본 인증은 사전 검사 중 평소처럼 수명이 짧은 API 자격 증명을
생성하고 폐기할 수 있습니다.

선택한 인스턴스, 소스, 네임스페이스, Review 호스트를 검토한 뒤 실제 승인 검사를 명시적으로
시작하세요.

```sh
node tests/e2e/guided-preview-live.js --apply /root/private-preview-acceptance/input.json
```

자격 증명은 선택한 컨트롤러의 저장된 구성에서 프로세스 메모리로 읽어옵니다. GitLab 관리자
API 토큰에는 고유한 승인 검사 이름이 있으며, 요청 입력으로만 전달하고 완료 또는 실패 시
폐기합니다. 명령 인수나 입력 파일에 토큰, 암호, 개인 키를 넣을 필요가 없습니다. 원시 하위
프로세스 오류, 작업 추적, HTTP 본문은 보고서에서 제외됩니다. 보고서는 운영자별 프로젝트와
작업 ID를 기록하므로 비공개입니다.

## 검증 항목과 보관 결과

적용에는 초기 관리형 등록이 필요하며 대상 프로젝트가 없어야 합니다. 실제 기본 가져오기는
새로운 자체 인스턴스 프로젝트 ID와 정상적인 기본 브랜치 푸시 파이프라인을 만듭니다.
도구는 실제 Runner에서 필수 `build:source`, `test:browser`, `build:wizard`, `test:wizard`
작업이 성공할 때까지 기다립니다. 실제 아티팩트를 읽고 기본 증거 계약을 사용해 소스 커밋,
파이프라인/이미지 식별 정보, 승인된 생성기 체크섬, 프로젝트 병합 게이트를 검증한 뒤 채택을
승인합니다.

어댑터는 동일한 인증 API로 설정을 재개합니다. 소유한 브랜치 하나와 MR을 만들고,
해당 MR의 일반 필수 네이티브 검사가 완료될 때까지 기다린 뒤 실제 수동 Review Deploy 및 Stop 작업을 실행합니다.
라우팅된 HTTPS 페이지, 실행 중인 후보 컨테이너 및 정확한 소유권/세대 라벨을 확인합니다.
Stop은 해당 컨테이너를 제거하고 일치하는 중지된 세대와 하한을 보존해야 합니다.

이어서 동일한 MR은 검증된 소스 SHA에 고정된 상태로 프로젝트의 일반 파이프라인 및 토론 게이트를 거쳐 병합됩니다.
게이트 우회, CI 건너뛰기 또는 추가 파이프라인 트리거는 사용하지 않습니다.
그 결과 발생한 기본 브랜치 푸시는 네 가지 필수 네이티브 작업과 일치하는 불변 빌드/브라우저 아티팩트 검증을 통과해야 합니다.
Beta가 활성화되면 어댑터는 해당 파이프라인의 수동 Beta Deploy 및 Stop 작업을 실행하고,
HTTPS 페이지, 컨테이너 및 일치하는 중지된 세대를 확인합니다.
전체 일회용 게이트는 Beta를 활성화하며 선택적 운영자 입력에서는 비활성화할 수 있습니다.
정확히 가져온 기본 브랜치, MR 및 병합된 기본 브랜치 빌드 컨텍스트가 필요합니다.
추가 System 마이그레이션이나 운영 환경 승격은 포함되지 않습니다.

정확한 기본 구성 바이트와 실행 중인 불변 운영 환경 이미지 ID는 전체 과정에서 변경되지
않아야 합니다. 설정의 소스 우선 연결과 원하는 미리 보기 설정은 의도적으로 구성된 상태로
남습니다. 소스 프로젝트, 병합된 MR 및 파이프라인 증거는 검토할 수 있도록 유지되며,
일반 병합은 소스 브랜치 삭제를 요청합니다. 정식 소스와 승인된 이력은 보존됩니다.
배포 또는 페이지 검사가 실패하거나 Deploy 응답이 유실되면 Review/Beta Stop 정리를 각각 독립적으로 시도합니다.
미리 보기 정리가 실패해도 마지막 운영 환경 불변 검사와 임시 토큰 취소는 계속 실행됩니다.

적용이 통과한 보고서에는 `acceptancePassed: true`가 있습니다. 승인을 기록하기 전에 개별
단계 결과와 실제 프로젝트/파이프라인/작업 ID를 읽으세요. 일부 기본 작업이 통과했어도 중단되거나
실패한 실행은 미완료입니다. 복구 전에 저장된 안내형 설정 상태, 소스 프로젝트, 정확한 Review
세대를 검사하세요. 정제된 전체 게이트 증거는 복구/보고서 정리 후에도 네이티브 소스, MR,
병합, 수동 작업 및 중지된 세대의 식별 정보를 보존하며, 인증 정보, 플랫폼 URL 및 원시 응답은 제외합니다.
수명 주기 단계가 누락되거나 실패하면 후속 버전 게시를 승인할 수 없습니다.
콜드 복구는 두 번째 소유 후보를 생성합니다. 안내형 단계는 원래 호스트에 속하고,
마이그레이션/스토리지 단계는 복원된 호스트에 속합니다.
게시 절차는 원래 안내형 기록을 `guidedPreviewReceipt` 아래에 중첩하여 두 증거를 하나의 아티팩트에 고정합니다.
실행 계보, 소스 리비전, CI 프로젝트/파이프라인/작업, 준비된 이미지 쌍 및 복원된 정식 연결 증거를 검사하며,
원래 안내형 단계를 복원 호스트에서 수행한 작업으로 바꾸어 표시하지 않습니다.
Stop 작업이 실패했다면 해당 소유 세대에 기존 네이티브 Stop/조정 절차를 사용하세요.
소유권 충돌을 우회하려고 라이브 환경 임대를 지우거나 다른 소스 이름으로 설정을 반복하지 마세요.

임시 토큰 생성의 완료 응답이 유실되면 도구는 정확히 예약된 이름
`guided-preview-acceptance-<operation>`을 정리하려고 시도하며,
활성 토큰이 관찰되지 않아도 정리 상태가 불확실하다고 보고합니다.
원래 네이티브 요청은 나중에 완료될 수 있습니다.
운영자 인스턴스에서는 정리가 완료되었다고 판단하기 전에 네이티브 GitLab 제어를 통해
해당 작업이 소유한 정확한 토큰을 검사하고 취소하세요.
일회용 게이트는 해체 중 자체 소유 데이터베이스를 제거합니다.
