# 빠른 시작 후 선택적 개발 미리보기

빠른 시작은 승인된 공개 System 컨트롤러와 Wizard를 시작합니다.
개발 미리보기는 이후 선택적으로 실행하는 작업입니다.
먼저 일반 설정, GitLab 초기화, 레지스트리 및 Runner 등록을 완료하세요.
일반 설치는 미리보기를 활성화하지 않고 계속 사용할 수 있습니다.

## 준비 사항 및 명시적 입력값

GitLab 네임스페이스와 기준 Wizard 소스 프로젝트를 제공하세요.
기존 비공개 프로젝트를 선택하거나 공개 HTTPS 업스트림/포크를 새 비공개 프로젝트로 가져오세요.
가져오기는 브랜치/태그 이력을 보존하며, 대상이 이미 사용 중이거나 가져온 참조가 바뀌면 설정을 중단합니다.
비공개 원본은 일반 GitLab 인증 정보로 별도로 가져온 뒤 기존 소스로 선택하세요.
원본 인증 정보를 저장 설정에 넣으면 안 됩니다.

복제는 선택한 원본의 기본 브랜치에서 시작하고 브랜치와 태그를 유지합니다.
운영 이미지 고정은 소스 브랜치를 선택하지 않으며, 공개 원본의 기본 브랜치가
승인된 릴리스의 Wizard 리비전과 일치함을 보장하지도 않습니다.
가져오기 전에 자신의 포크에서 원하는 기본 브랜치를 선택하고 새 GitLab 프로젝트의 실제 기본 브랜치를 확인하세요.
설정은 해당 브랜치의 실제 커밋과 네이티브 푸시 파이프라인을 검증합니다.
정확한 소스 상태를 사용하려면 먼저 GitLab에 가져와 기본 브랜치를 선택한 뒤
**기존 비공개 소스 프로젝트 사용**을 선택하세요. 설정은 기존 선택을 유지합니다.

Wizard 소스에는 검토된 네이티브 배포 CI, 현재 일반 빌드 레시피 및 환경 실행기가 포함되어야 합니다.
안내형 설정은 브라우저와 환경 실행기를 포함한 네이티브 CI 생성 파일을
승인된 컨트롤러에 고정된 Wizard 소스 스냅샷과 비교하여 검증합니다.
이 생성 파일을 검토 후 변경한 포크는 명시적인 소스 기준 매니페스트 절차를 대신 사용합니다.
안내형 설정은 자체 보고한 해시를 승인하지 않습니다.
기존 프로젝트는 `.gitlab/primary.yml`을 선택하고,
파이프라인 성공 및 토론 해결 병합 조건을 활성화한 상태로 유지하며,
온라인 Docker Runner에 필수 `docker` 및 `wizard-source-primary` 태그를 부여해야 합니다.
설정은 비공개 배포를 활성화하며 기존 게시 역할은 변경하지 않습니다.
새 가져오기는 포크가 업스트림 게시 대상을 상속하지 않도록 공개 게시 선택 항목을 명시적으로 비활성화합니다.

Runner 데몬에 검토된 변경 불가능한 System 도우미를 준비하고,
[환경 안내서](../project-bootstrap/wizard-environments/README.md)에 따라
`SYSTEM_WIZARD_ENVIRONMENT_IMAGE`와 `SYSTEM_WIZARD_CANONICAL_CONTROLLER`를 설정하세요.
서로 다른 정확한 Review/Beta HTTPS 호스트, 기존 Wizard 주소로 해석되는 공개 DNS,
`/ssl` 아래의 유효하고 일치하는 인증서/비공개 키를 사용하세요.
사전 검사는 소스를 준비하기 전에 DNS, 정확한 인증서 식별 정보와 날짜,
일치하는 키, 소스 사용 가능 여부 및 Runner 접근을 확인합니다.
설정은 인증서를 발급하거나 DNS를 변경하지 않습니다.

## 안내형 설정 및 대기

Wizard에 연결하여 **개발 미리보기 설정**을 선택하세요.
네임스페이스, 소스 프로젝트, 가져올 원본 및 명시적 HTTPS 입력값을 선택하세요.
Review는 기존 단일 병합 요청 임대를 사용하는 공유 호스트 하나이며 Beta는 선택 사항입니다.
**원하는 설정 저장**은 설정 백업에 담을 의도만 변경합니다.

**준비 사항 검사**를 선택하고 선택한 입력값을 확인한 뒤 설정을 명시적으로 확인하세요.
소스 전송은 만료되는 프로젝트 인증 정보로 새로 소유한 빈 프로젝트에 네이티브 Git 푸시를 수행합니다.
전송이 끝나면 인증 정보를 취소하며 설정 내보내기에 포함하지 않습니다.
소스를 가져오면 실제 기본 브랜치 푸시 파이프라인이 시작됩니다.
기존 프로젝트에 현재 네이티브 푸시 파이프라인이 없다면 정상적인 소스 푸시가 필요합니다.

빌드, 소스 검사 및 독립 브라우저 검사는 Runner 대기열, 다운로드 및 호스트 자원에 따라
추가로 몇 분 이상 걸릴 수 있습니다. 대기 중인 설정은 파이프라인 링크를 표시합니다.
완료되면 준비 사항을 다시 검사하고 계속하세요.
필수 검사 실패, 누락된 아티팩트, 변경된 CI 또는 불일치하는 변경 불가능한 이미지로는
승인된 연결을 만들 수 없습니다.
네이티브 [소스 기준 검증기](../project-bootstrap/wizard-source-primary/README.md)가
정확한 커밋, 파이프라인, 승인된 생성 파일 및 다이제스트를 다시 확인합니다.

초기 설정에는 수정되지 않은 관리형 등록과 보존된 설치 식별 정보가 필요합니다.
공개 설치는 승인된 컨트롤러/Wizard 릴리스 기록을 보존합니다.
이전 설정을 보관하고 주 설정이나 운영 이미지 선택을 변경하지 않은 채 비공개 미리보기를 연결합니다.
기존 관리형 소스 이력은 네이티브 연결/업그레이드 경로를 사용해야 합니다.
운영 환경 승격은 별도로 유지됩니다.

증거 조회는 각 검증 단계 안에서 크기가 제한된 묶음으로 처리됩니다.
프로젝트, 파이프라인, 아티팩트 및 생성 파일에 대한 동일한 검사를 유지하며,
계획을 적용할 때 캐시된 미리보기를 신뢰하는 대신 변경 가능한 증거를 새로 가져옵니다.
이렇게 하면 Rails를 개별적으로 시작하는 횟수가 줄어듭니다.
다운로드, 네이티브 빌드 및 브라우저 검사는 여전히 실제 실행 시간이 필요하며,
설정에 걸리는 시간을 고정된 값으로 약속하지 않습니다.

### 소스에서 빌드한 설치의 식별 정보 보존

소스에서 빌드한 설치는 승인된 공개 릴리스라고 주장하지 않고도 실제 실행 중인 이미지 쌍을 보존할 수 있습니다.
설정된 두 이미지 선택자는 모두 변경 불가능한 `sha256:` 이미지 ID여야 합니다.
컨트롤러와 Wizard에는 서로 일치하는 `org.system-bootstrapper.test-job` 및
`org.system-bootstrapper.source-tree` 라벨, 각자의 `org.opencontainers.image.revision` 라벨,
그리고 Wizard에는 일치하는 `org.system-bootstrapper.source-revision` 라벨이 있어야 합니다.
패키지에 포함된 Wizard 스냅샷은 제공된 Wizard 리비전과 일치해야 합니다.
네이티브 System 후보 준비 절차는 커밋된 체크아웃에서 이 쌍의 출처 증거를 생성합니다.

예상 이미지 ID, System 커밋/트리 및 Wizard gitlink는 검토된 소스/빌드 기록에서 독립적으로 확보하세요.
커밋된 컨트롤러 진입점을 통해 이미 실행 중인 쌍을 기록하세요.

```sh
docker exec system_bootstrapper_1 node /system/bootstrapper/record-source-installation.js \
  --controller sha256:REPLACE_WITH_CONTROLLER_IMAGE_ID \
  --wizard sha256:REPLACE_WITH_WIZARD_IMAGE_ID \
  --source-revision REPLACE_WITH_SYSTEM_COMMIT \
  --source-tree REPLACE_WITH_SYSTEM_TREE \
  --wizard-revision REPLACE_WITH_WIZARD_GITLINK
```

이 명령은 실제 실행 중인 컨테이너와 정확한 이미지 출처를 검사한 뒤,
root 소유의 0600 권한 파일 `/state/.source-installation.json`을 생성합니다.
이미지를 설치, 시작, 승격 또는 승인하거나, 주 설정을 변경하거나,
릴리스 기록을 생성하거나, 테스트가 통과했다고 주장하지 않습니다.
이후 설정에서는 실행 중인 식별 정보를 다시 확인합니다.
기존 공개 릴리스 선택이 잘못되었거나 불완전하면 이 소스 기록으로 대체할 수 없습니다.
복구 후 새로운 초기 설정을 시작하기 전에 소스 출처를 보존하거나,
독립적으로 보존한 빌드 입력값을 기준으로 명시적으로 다시 기록하세요.
설정 메타데이터만으로는 이 작업을 허가할 수 없습니다.

## 배포, 중지 및 System 후보

준비가 끝난 설정은 예약된 Review URL을 표시합니다.
명시적인 네이티브 **배포** 수동 작업이 성공하면 사용할 수 있으며,
**중지**는 기존 소유권 삭제 표식을 유지합니다.
기준 도우미는 Review 소유권, 세대 하한, 성공한 후보 증거 및 별도의 Beta 제어를 계속 적용합니다.
설정은 후보를 자동으로 배포하지 않습니다.

같은 네임스페이스에서 별도의 System 소스 프로젝트를 선택할 수도 있습니다.
그러면 기준 Review 호스트를 대상으로 기존 Wizard 전용 병합 요청 미리보기 작업을 활성화합니다.
검사한 각 System 후보를 수동 배포하려면 여전히 기존의 명시적인
[System 후보 연결](../project-bootstrap/system-review/bind.js)이 필요합니다.
일회용 전체 플랫폼 마이그레이션 네트워크는 별도의 검증 조건입니다.

## 백업, 재생성 및 안전한 계속 진행

일반 JSON/ZIP 내보내기는 `previewSetup`에 버전이 지정된 원하는 설정을 담습니다.
네임스페이스/프로젝트 이름, 원본 선택 및 HTTPS 경로를 포함하며,
새 인스턴스 프로젝트 ID, 소스 전송 인증 정보, 파이프라인 증거 또는 실제 배포 기록은 포함하지 않습니다.
이 필드가 없는 이전 백업도 계속 사용할 수 있습니다.
설정을 열거나 가져와도 설정 작업이 시작되거나 운영 환경이 변경되지 않습니다.

일치하는 Seed 없이 재생성한 뒤에는 새 인스턴스에서 설정을 명시적으로 실행하여
새 ID, 인증 정보 및 증거를 만드세요. 설정 백업만으로는 GitLab 저장소,
레지스트리 이미지 또는 CI 아티팩트가 복원되지 않습니다.
Harvest/Seed는 계속 서비스 데이터 복구 경로입니다.

설정은 소스, 연결 및 환경 변경 전 과정에서 네이티브 프로젝트 및 운영 상태 임대를 유지하므로
설정 보내기, Harvest 및 호스트 유지보수가 겹칠 수 없습니다.
읽기 전용 설정 상태 조회 또는 작업 폴링은 계속 사용할 수 있습니다.

같은 인스턴스 안에서는 같은 작업을 반복하여 대기 중인 작업을 계속하세요.
비공개 작업은 소유한 프로젝트 ID와 설정 해시를 보존합니다.
원본 변경, 운영자 수정, 소유권 충돌 또는 다른 운영 설정은 계속 진행을 중단합니다.
시간 초과, Docker 전송 손실 또는 불완전한 종료 응답 등으로 Rails 완료가 확인되지 않으면
`needs-inspection`을 기록하고 두 개의 정확한 소유 임대를 모두 유지합니다.
상태는 읽기 전용으로 유지되며 사전 검사와 적용으로 그 작업을 계속할 수 없습니다.
관리자는 대상 복구 전에 기록된 변경이 종료되었는지 확인하고 프로젝트, 참조 및 변수의 결과를 검사해야 합니다.
로컬 작업 실패만으로 Rails가 멈췄다고 판단할 수는 없습니다.
명확하게 완료된 네이티브 거부는 자체 임대를 해제하고 일반적인 명시적 계속 진행을 허용합니다.

갑작스러운 프로세스 손실 후 남은 작업 잠금은 대상 복구 전에 정확한 소유자를 확인해야 합니다.
충돌을 우회하려고 프로젝트를 삭제하거나, 실행 기록을 초기화하거나,
임대를 제거하거나, 강제로 푸시하지 마세요.

비공개 설정 파일을 선호하는 운영자는 동일한 저장소 관리 컨트롤러 진입점을 사용할 수 있습니다.

```sh
docker exec system_bootstrapper_1 node /system/project-bootstrap/preview-setup/run.js status
docker exec system_bootstrapper_1 node /system/project-bootstrap/preview-setup/run.js preflight /state/preview-settings.json
docker exec system_bootstrapper_1 node /system/project-bootstrap/preview-setup/run.js apply /state/preview-settings.json PREFLIGHT_HASH
```

파일 권한은 `0600`을 사용하세요. 정확히 확인한 해시와 Wizard와 동일한 버전별 설정을 제공하세요.
상태 조회는 읽기 전용이며 사전 검사는 프로젝트, 파이프라인 또는 배포를 생성하지 않습니다.
적용은 명시적으로 확인한 네이티브 설정만 수행합니다.
반환된 Review URL은 호스트를 예약하는 것이며 수동 배포가 성공하기 전에 미리보기가 실행 중이라고 주장하지 않습니다.
