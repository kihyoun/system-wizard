# 가져온 Wizard 빌드 및 검증

관리형 CI 활성화는 [소스 초기화](WIZARD_SOURCE.md) 후 후보를 빌드하고 검증합니다.
빌드를 활성화해도 실행 중인 Wizard는 유지됩니다. Review/Beta는 별도의
[수동 환경 작업](../project-bootstrap/wizard-environments/README.md)을 사용하며,
운영 환경은 보호된 [운영자 승격 명령](../project-bootstrap/wizard-production/README.md)을 사용합니다.

## 미리보기 및 활성화

전체 브라우저 절차는 [Wizard 수동 빌드 및 검사](HANDBOOK.md#build-and-check-the-wizard-manually)를 참조하세요.
일치하는 System 이미지에 준비된 소스 패키지, 등록된 관리형 프로젝트,
사용 가능한 프로젝트 레지스트리, Docker/Buildx와 레지스트리에 접근할 수 있고
`docker` 태그를 수락하는 검토된 Runner가 필요합니다.
시작하기 전에 실제 디스크/RAM 여유를 확인하세요. 이 절차는 애플리케이션과 브라우저 이미지를 빌드하므로
자원이 제한된 호스트에서는 다른 인프라 빌드와 경쟁하지 않도록 해야 합니다.
공유 Runner가 이미 이 조건을 충족하면 추가 프로젝트 Runner는 필요하지 않습니다.

일치하는 System/Wizard 버전을 사용하고 소스 초기화를 완료한 뒤 플랫폼의 GitLab 레지스트리를 설정하세요.
Sync에 연결하고 가져오기로 관리형 프로젝트를 불러온 다음 행을 펼치세요.
**Wizard 빌드 및 검증**을 선택하여 소유한 저장소, 가져온 커밋 및 관리되는 레시피 버전을 확인하세요.

미리보기를 열어도 저장소 파일이나 파이프라인은 변경되지 않습니다.
**빌드 파이프라인 활성화**는 미리 본 레시피 해시를 명시적으로 확인합니다.
비동기 작업은 별도의 관리형 레시피를 설치하고 업스트림 게시 파일을 보존하며,
기록된 초기 파이프라인을 시작하거나 복구합니다. 운영 환경은 유지됩니다.
대기 중인 미리보기는 닫아도 안전하며 활성화 요청 중에는 닫기가 비활성화됩니다.
**상태 새로고침**은 동일한 작업 폴링 계약으로 기록된 파이프라인/검사를 조회합니다.

## 상태 및 안전한 계속 진행

| 상태 | 조치 |
| --- | --- |
| 활성화 예약됨 / 레시피 설치됨 | 상태를 새로고침하거나 최신 미리보기를 검토하고 명시적으로 활성화를 계속하세요. |
| 파이프라인 실행 중 | 파이프라인을 확인하거나 나중에 상태를 새로고침하세요. |
| 필수 검사 실패 | GitLab에서 실패한 작업을 확인하거나 재시도한 뒤 같은 작업의 상태를 새로고침하세요. |
| 후보 검증 완료 | 컨트롤러가 필수 검사와 일치하는 변경 불가능한 아티팩트 증거를 검증했습니다. 운영 환경은 유지됩니다. |
| 파이프라인 결과 조정 필요 | 새로고침만 하세요. 복구 전에 관리자가 영구 작업/체크포인트와 GitLab을 확인해야 합니다. 확인 없이 체크포인트를 지우지 마세요. |
| 검증 실패 | 이전 아티팩트 증거는 숨겨집니다. 오류를 확인하고 새로고침하세요. 안전하게 명시적으로 계속하기 전에 최신 미리보기를 검토하세요. |

**활성화 계속**은 최신 미리보기를 확인한 뒤 대기 중, 레시피 설치됨 또는 검증 실패 상태에서만 제공됩니다.
상태 요청이나 실패는 이전 미리보기 확인을 무효화합니다.
**미리보기 새로고침**으로 새 확인을 받으세요. 서버의 소유권, 예상 내용 및 영구 파이프라인 검사가
최종 판단 기준이며 버튼으로 우회할 수 없습니다.
생성 결과가 불확실하면 확인 없는 두 번째 활성화는 제공하지 않습니다.

이미지 참조는 `candidate-verified` 상태일 때만 표시되며,
단순히 파이프라인이 성공했거나 이전 아티팩트가 캐시되어 있다는 이유로 표시되지 않습니다.
검증에 실패하면 즉시 숨깁니다. 이미 활성화된 빌드 레시피를 업그레이드할 때
일반 소스 가져오기를 사용하면 안 됩니다.

## 파이프라인 및 후보 증거 확인

GitLab에서 새 파이프라인을 시작하는 대신 대화상자의 **파이프라인 열기**로 기록된 작업을 확인하세요.
관리형 CI 설정은 `.system-bootstrapper/ci.yml`이며,
보존된 업스트림 `.gitlab-ci.yml`은 이 작업으로 활성화되지 않습니다.

| 작업 | 수행 내용 및 증거 |
| --- | --- |
| `build:wizard` | 커밋된 잠금 파일로 설치하고 선택한 도구 모음 검사를 실행하며 후보를 게시합니다. 소스 커밋, 파이프라인 ID 및 변경 불가능한 레지스트리 다이제스트를 `build-evidence.json`에 기록합니다. |
| `test:wizard` | 해당 변경 불가능한 이미지를 다운로드하고 HTTP 및 브라우저 렌더링/프로젝트/SPA 이동을 검사합니다. 일치하는 식별 정보를 `wizard-evidence.json`에 기록하며 `browser-evidence/`에는 브라우저 결과와 스크린샷이 들어 있습니다. |

각 작업의 제한 시간은 30분입니다. 설정된 아티팩트 보관 기간은 7일입니다.
브라우저 스크린샷만으로 소스/이미지 식별 정보를 검증할 수 없으며,
이미지 푸시 성공만으로 브라우저 검사 통과를 입증할 수도 없습니다.
컨트롤러가 **검증된 후보 이미지**를 표시하려면 두 필수 작업과 서로 일치하는 아티팩트 증거가 모두 검증되어야 합니다.
참조는 `registry/repository@sha256:…` 형식이며 변경 가능한 태그는 동등한 증거가 아닙니다.

같은 파이프라인에서 작업을 재시도한 뒤 상태를 새로고침하세요.
증거가 만료되거나 검증에 실패했다고 대체 아티팩트를 만들거나 작업 체크포인트를 지우지 마세요.
보고된 오류를 확인하고 최신 미리보기에서 제공하는 보호된 계속 진행만 사용하거나 관리자에게 조정을 요청하세요.
인수 검사 증거를 보관할 때 파이프라인/커밋/이미지 식별 정보를 기록하고,
설정, 인증 정보 및 토큰은 보고서에 넣지 마세요.

빌드 레시피에는 빌드와 테스트 단계만 있습니다. 별도의 환경 레시피를 설치하면
수동 Review/Beta 작업이 추가됩니다. 어느 레시피도 운영 배포 작업을 활성화하지 않습니다.
운영 환경 승격에는 명시적인 운영자 계획과 확인이 필요합니다.

## 컨트롤러 API

모든 경로에는 기존 Sync Bearer 인증이 필요합니다.

| 경로 | 계약 |
| --- | --- |
| `GET /projects/wizard/build` | 읽기 전용 저장소/소스/레시피 미리보기와 저장된 빌드 상태. |
| `POST /projects/wizard/build` | 명시적 `{recipeHash}` 활성화. 비동기 작업을 반환합니다. |
| `GET /projects/wizard/build/status` | 안전한 비동기 새로고침. 활성화되지 않았으면 파이프라인 생성 없이 `not-activated`를 반환합니다. |
| `GET /projects/jobs/:id` | 기존 폴링 엔드포인트. 완료 시 `{build,message}`를 반환합니다. |

Runner/시작 작업과 다른 프로젝트 변경은 보호됩니다.
이 빌드의 활성 작업에 대한 반복 요청은 기존 작업을 반환합니다.
상태 새로고침은 파일을 설치하거나 파이프라인을 생성하지 않습니다.

## 도구 모음 프로필

Vite를 사용하는 새 소스 가져오기는 `node24-vite8-quickstart-v5` 프로필을 선택합니다.
고정된 Node 24/npm 도구 모음, 잠금 파일 설치, 린트, Vitest, TypeScript/Vite 빌드,
설정 내보내기 검사 및 Playwright 브라우저 검사를 사용합니다.
브라우저 증거에는 렌더링된 UI, 프로젝트, SPA 이동, 설정 ZIP 및 정확한 Cube 검증이 포함됩니다.
정확히 고정된 버전은 `wizard/package.json`과 관리형 레시피를 확인하세요.

이 프로필은 정확한 태그 정리와 빌드/브라우저 이미지의 공개 CA 신뢰를 유지합니다.
신뢰 데이터는 System 소스에 포함된 검토되고 체크섬이 확인된 Mozilla 번들에서 가져옵니다.
Node는 이 갱신된 OpenSSL 신뢰 저장소를 사용합니다.
갱신은 작업 이미지를 빌드하거나 준비할 때 실행하며,
런타임에 새 신뢰 번들을 다운로드하거나 호스트의 신뢰 저장소를 변경하지 않습니다.

브라우저 검사는 **작동 방식**, 개요 카드 세 개,
**System Bootstrapper 설치**의 스크롤/포커스 동작 및 정확한 **빠른 설치** 명령을 검증합니다.
통합 안내서를 열고, 개요/문서/Wizard를 이동할 때 선택한 프로젝트 작업 공간을 유지하며,
설정 ZIP/Cube를 검증하고 중첩 SPA 및 직접 `/configuration` 경로를 확인합니다.
이 프로필에는 현재 인터페이스가 필요합니다. 기존 overview-v3 및 CA-v4 예약은
과거의 **시작하기** / **Wizard 열기** 검사를 유지합니다.

기존 관리형 가져오기는 일치하는 소스와 함께 `"buildProfile": "node24-vite8-quickstart-v5"`를 지정하여
보호된 빌드/환경 전용 업그레이드를 사용하세요. 연결된 소스 기준 프로젝트는 대신
[네이티브 소스 병합 및 연결 새로고침](../project-bootstrap/wizard-source-primary/README.md#refresh-an-existing-source-primary-build-recipe)을 사용합니다.
모든 이전 프로필은 정확한 과거 해시를 유지합니다.
현재 동등한 레거시 프로필은 `legacy-ca-v4`입니다.

예약된 과거 레시피는 레거시 Node 13/CRA/Jest 레시피를 포함해 정확한 해시로 계속 검증할 수 있습니다.
과거 호환성을 유지한다고 오래된 도구 모음이 새 프로젝트에 적합해지는 것은 아닙니다.
가져온 프로젝트를 업그레이드하려면 보호된
[소스/도구 모음 마이그레이션](../project-bootstrap/wizard-upgrade/README.md)이 필요합니다.
컨트롤러 이미지를 바꾸어도 기존 예약은 다시 작성되지 않습니다.
소스가 이미 현대화되어 로컬 개발 내용을 유지해야 한다면 빌드/환경 전용 업그레이드를 사용할 수 있습니다.
컨트롤러 업그레이드가 기존 레시피 예약을 자동 갱신하지 않습니다.
영향받는 작업 이미지를 다시 빌드하려면 명시적인 버전별 마이그레이션을 사용하세요.

## 검증

격리된 API, 레시피 및 어댑터 픽스처는 명시적 확인, 계속 진행, 실패/상태 표시,
소유권 및 변경 보호를 검사합니다.

```sh
node tests/wizard/build-recipe.js
node tests/wizard/build-workflow.js
ruby tests/gitlab/wizard-build.rb
```

이 픽스처는 실행 중인 GitLab에 접속하지 않습니다. 전체 통합 검사에는 실제 소유 프로젝트,
성공한 필수 작업, 일치하는 변경 불가능한 레지스트리 아티팩트,
브라우저 증거 및 작업 소유 자원 정리도 필요합니다.
승격 전에 실제 파이프라인 결과를 확인하세요. 후보 아티팩트만으로 운영 배포가 완료되는 것은 아닙니다.
토큰과 비공개 설정을 보고서에 넣지 마세요.
