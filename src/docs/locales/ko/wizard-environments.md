# 관리형 Wizard Review와 Beta

환경 작업 흐름은 관리형 소스/빌드 영수증을 확장합니다. 운영 환경 승격과 롤백은 이
레시피의 범위 밖입니다. 기존 공개 소스 CI와 게시 대상은 유지됩니다.

Review는 하나의 정확한 HTTPS 호스트와 하나의 활성 Merge Request 임대를 사용합니다.
리소스 식별 정보에는 프로젝트와 MR IID가 포함됩니다. 다른 MR은 현재 Review를 중지할
때까지 기다려야 하며, 같은 MR의 더 새로운 검증된 파이프라인은 이를 교체할 수 있습니다.
Beta는 별도의 정확한 호스트와 현재 기본 브랜치의 헤드를 사용합니다. 두 환경 모두
Deploy와 Stop은 수동 네이티브 GitLab 작업입니다. 운영 환경 작업이나 임의 이미지
배포 엔드포인트는 없습니다.

## 구성과 설치

인증된 Wizard 환경 대화 상자는 선택적 설정을 미리 보여 줍니다. 활성화한 각 행에는
명시적인 정확한 호스트, 도메인 모드 2 및 /ssl 아래의 인증서/키 경로가 필요합니다.
이 레시피는 와일드카드 도메인 모드를 지원하지 않습니다. 비활성 행은 비워 둘 수 있습니다.
설정을 추정하여 자동으로 활성화하지 않습니다.

서버는 현재 운영 환경 호스트 주소에 대한 DNS, 정확한 인증서 적용 범위와 유효성,
일치하는 개인 키를 검증합니다. 플랫폼 및 다른 프로젝트 경로와 별도로 호스트를 예약하세요.
설치를 확인하기 전에 인증서를 준비하세요. 기존 운영 환경 설정과 고정 HTTPS www URL
및 포트 8071을 포함하는 불변 System Cube는 그대로 유지됩니다.

확인된 미리보기는 보호된 skip-CI 커밋 하나로 버전 관리되는 파일과 선택한 CI를 설치합니다.
파이프라인을 시작하거나 컨테이너를 배포하지 않습니다. 예상하지 못한 편집, 사용 중인
경로, 변경된 미리보기 및 소유권 불일치는 안전하게 거부됩니다. Refresh는 다른 커밋이나
파이프라인을 만들지 않고 동일한 작업을 검사합니다. 커밋 결과가 불확실하면 재시도 전에
조정해야 합니다. 설치가 검증된 작업은 수동 CI 작업을 실행할 준비가 된 상태입니다.

설정을 바꾸려면 먼저 활성 환경을 중지하고 대기 중인 작업을 조정하세요. 다시 미리 보고
변경을 명시적으로 확인하세요. 업데이트는 관리 내용을 교체하기 전에 이전 레시피와
정확한 파일 식별 정보를 확인합니다. 가져오기/보내기와 컨트롤러 시작 전후에 서버 소유
영수증을 보존하세요. 이전 빌드 증거는 과거 기록으로 남습니다. 설치된 레시피에는 환경
상태를 사용하세요.

## 불변 도우미 프로비저닝

운영자는 검증된 커밋 소스와 이에 일치하는 검증된 Wizard 스냅샷으로 깨끗한 System
이미지를 빌드해야 합니다. 비공개 구성, 자격 증명, Git 메타데이터 또는 호스트 런타임
출력을 포함하지 마세요. 기존 Runner Docker 데몬에 해당 이미지를 프로비저닝하고,
레시피가 설치된 동안 보존하며, SYSTEM_WIZARD_ENVIRONMENT_IMAGE에 정확한
sha256 이미지 ID를 설정하세요. SYSTEM_WIZARD_CANONICAL_CONTROLLER는
system_bootstrapper_1을 식별해야 합니다. UI는 도우미 이미지나 표준 컨트롤러를
선택할 수 없습니다.

하위 모듈이 초기화된 일치하는 System 체크아웃에서 전체 도우미 이미지를 빌드하기 전에
고정 소스 패키지를 준비하세요.

```sh
bash project-bootstrap/wizard-source/prepare.sh
docker build -f system/Dockerfile -t system-wizard-helper:local .
docker image inspect --format '{{.Id}}' system-wizard-helper:local
```

반환된 이미지 ID를 비공개 컨트롤러 구성에 기록하고 정확히 그 이미지를 Runner의
Docker 데몬에서 사용할 수 있게 하세요. 독립 실행형 런타임 베이스는 전체 도우미가
아닙니다. 고정 스냅샷 계약은 [소스 패키징](../../docs/WIZARD_SOURCE.md)을 확인하세요.

CI는 일반적인 작업 범위 레지스트리 자격 증명으로 후보 다이제스트를 미리 로드합니다.
Sync/관리자 자격 증명은 도우미에 들어가지 않습니다. 도우미는 기존의 신뢰된 Docker
Runner 모델과 원래의 컨트롤러/GitLab 컨테이너로 표준 영수증과 작업을 검사합니다.
이는 악의적인 저장소 코드를 위한 격리가 아닙니다. 도우미는 범위가 제한되며 network
none, 읽기 전용 루트 파일시스템, 기존 Docker 소켓, templates 볼륨 및 읽기 전용
SSL 볼륨을 사용합니다. 새 구성 볼륨은 받지 않습니다.

배포 전에 정확한 실행 작업, 파이프라인, 소스 헤드, MR 식별 정보, 선택된 CI 및 성공한
필수 빌드/브라우저 아티팩트를 서버에서 확인합니다. 임시 검증 접속은 GitLab 안에만
유지되고 폐기됩니다. 이 레시피를 업그레이드할 때는 도우미 이미지를 명시적으로 다시
프로비저닝해야 합니다. 관련 없는 이미지 정리 과정에서 삭제하지 마세요.

## 소유권과 복구

Deploy/Stop은 공유 표준 컨트롤러 잠금과 보호된 영수증 갱신을 통해 직렬화됩니다.
후보 컨테이너, 네트워크 및 경로 조각에는 정확한 작업/프로젝트/MR/세대 소유권이
있습니다. 후보가 정상 상태가 된 뒤 HTTPS 경로가 바뀝니다. nginx 검증, 다시 로드
또는 영수증 쓰기에 실패하면 이전 경로를 복원합니다. Stop은 소유권이 있는 HTTP 410 /
HTTPS 핸드셰이크 거부 tombstone을 유지하므로, 사용 가능한 후보 인증서가 없어도 중지한
호스트가 플랫폼 서비스로 연결되지 않습니다. 정리는 소유한 세대만 제거하며 오래된
작업은 더 새로운 배포를 교체하거나 중지할 수 없습니다.

호스트/프로세스의 갑작스러운 손실 후 잠금이 남아 있으면 운영자가 소유자와 정확한
도우미 컨테이너를 점검한 뒤 해당 대상만 복구해야 합니다. 재시도가 실패했다는 이유로
잠금, 영수증 또는 경로를 삭제하지 마세요. 대기 중인 전환과 퇴역 리소스는 조정을 위해
기록에 남습니다. 정리 목적으로 전역 Docker prune을 사용하거나 기본 플랫폼을
다시 시작하지 마세요.

구성은 Harvest/Seed와 별도로 유지됩니다. 환경 설치는 기본 개발 플랫폼을 선택하거나
실행 중인 운영 환경 Wizard를 승격하지 않습니다. 운영 환경은 별도의
[운영자 승격 작업 흐름](../wizard-production/README.md)을 사용합니다.

## 프록시 중단 없는 인증서 관리

운영자가 준비한 ACME webroot를 /ssl/acme-http01에서 공유하세요. 제공된 HTTP 템플릿은
일반 HTTPS 리디렉션 전에 /.well-known/acme-challenge/만 허용합니다. 기본 HTTP
챌린지 서버는 선택적 HTTPS 경로가 설치되기 전 새 후보 호스트를 처리합니다.
갱신을 위해 공유 프록시를 중지하지 마세요.

각 인증서 계보에 Certbot webroot 인증과 deploy hook을 구성하세요. 이 훅은 전체
체인과 개인 키를 구성된 /ssl/live/<lineage>/ 경로에 원자적으로 복사하고 nginx를
검증하여 정상적으로 다시 로드해야 합니다. 개인 키는 비공개로 유지하세요. 사용하지
않는 standalone 중지/시작 갱신 훅은 백업하고 시험 실행으로 webroot 갱신을 검증한
후에만 제거하세요. 발급과 갱신은 운영자 작업이며 CI 배포 권한에 포함되지 않습니다.

격리된 매니페스트는 환경 API/작업 흐름, 결정적 레시피, 보호된 GitLab 업그레이드,
도우미 소유권/복구 및 프록시 보존을 검사합니다. 폐기 가능한 플랫폼에서 실제 GitLab
수동 작업 실행, HTTPS/브라우저 동작 및 운영 환경 보존도 확인하세요. 픽스처 성공만으로
이러한 통합 관문이 입증되지는 않습니다.

## 단일 소스 기본 저장소

명시적으로 소스 기본 저장소로 채택된 Wizard 프로젝트는 애플리케이션 소스, 일반 검토
및 네이티브 빌드/환경 작업을 한 저장소에 유지합니다. `.gitlab/primary.yml`을 선택하며,
두 번째 애플리케이션 저장소나 인스턴스별 커밋 마커 파일이 필요하지 않습니다. 서버 소유
채택 영수증은 정확한 프로젝트 ID, 네임스페이스, 기본 브랜치 및 승인된 일반 CI/빌드
스크립트의 SHA-256 매니페스트를 결합합니다. 작업은 실제 파이프라인 커밋에서 해당
파일을 독립적으로 검증합니다. CI 생성기를 편집하려면 다시 검토된 채택이 필요하며,
애플리케이션 변경은 일반 Merge Request 작업 흐름을 따릅니다.

일반 작업 실행기는 `source-primary.sh`이며 애플리케이션의
`.gitlab/delivery/environment.sh`에 설치됩니다. `deploy review`, `stop review`,
`deploy beta` 또는 `stop beta`를 받습니다. 다음 프로젝트 CI 변수를 일반 환경 범위
`*`, 원시 값, 마스킹 및 보호 없음으로 구성하세요.

| 변수 | 운영자가 제공할 값 |
| --- | --- |
| `SYSTEM_WIZARD_ENVIRONMENT_IMAGE` | 정확하게 사전 프로비저닝한 깨끗한 System 도우미 이미지 ID, `sha256:…` |
| `SYSTEM_WIZARD_ENVIRONMENT_OPERATION` | 서버가 소유하는 새 48자리 16진수 예약 식별자 |
| `WIZARD_REVIEW_HOST` | 정확하게 구성한 Review HTTPS 호스트, 비활성 시 빈 값 |
| `WIZARD_BETA_HOST` | 정확하게 구성한 Beta HTTPS 호스트, 비활성 시 빈 값 |

`WIZARD_DELIVERY_ENABLED=true`는 이 인스턴스가 네이티브 이미지 빌드와 환경 작업에
참여하도록 합니다. 이 구성 값은 자격 증명이 아닙니다. 같은 프로젝트의 Merge Request
작업에서 사용할 수 있어야 합니다. 표준 도우미는 여전히 다른 프로젝트, 포크, 대체된
예약 또는 검증되지 않은 파이프라인에서 온 작업을 거부합니다. 운영 환경은 별도의
의도적인 승격으로 유지됩니다.

기존 관리형 프로젝트를 채택하기 전에 두 선택적 환경을 중지하고 기존의 소유권이 있는
중지 경로 정리를 사용하세요. 계획을 검토하고 이전 경로 조각과 그 소유 리소스가 모두
없음을 확인하세요. 채택은 활성, 대기 중 또는 퇴역 세대를 거부합니다. 완전한 이전 배포
스냅샷을 불변 이력에 보존하고 세대 하한을 새 예약으로 이어가세요. 하한을 초기화하거나
이전 프로젝트 tombstone을 새 프로젝트 기록으로 다시 작성하지 마세요. 예상하지 못한
잔여 경로는 새 도우미가 거부합니다.

인증된 환경 대화 상자는 계속 DNS와 인증서를 검증하고 명시적 미리보기로 설정을
갱신합니다. 소스 기본 프로젝트에서는 소스 커밋, 새 파이프라인 또는 운영 환경
재시작 없이 소유한 네 개의 CI 변수만 갱신합니다. 기존 잠금 아래에서 정확한 이전 값과
변수 메타데이터를 확인합니다. 중단된 부분 업데이트는 같은 작업을 유지합니다.
상태 조회는 쓰기 없이 이를 검사하며, 명시적 확인은 알려진 이전 값 또는 대상 값만
조정합니다. 예상하지 못한 변수 변경은 운영자의 조정이 필요합니다. 기존의 단일 Review
임대, 세대 보호, 제한된 도우미 정리, 롤백 및 중지 호스트 동작은 그대로 적용됩니다.
