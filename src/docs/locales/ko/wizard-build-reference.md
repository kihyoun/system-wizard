# 관리형 Wizard 빌드 후보

빌드 절차는 명시적인 미리보기/활성화 후 검사와 변경 불가능한 후보 레지스트리 아티팩트를 활성화합니다.
실행 중인 운영 Wizard를 유지하며 Review/Beta 배포와 운영 환경 승격은 별도 작업입니다.
업스트림 Wizard CI와 Dockerfile은 관리형 파일과 함께 계속 사용할 수 있습니다.

새 소스 가져오기는 소스에 맞는 버전별 레시피를 사용합니다.
Vite 스냅샷은 Node 24/Vite 프로필을 선택합니다.
과거 Node 13/CRA/Jest 레시피는 기존 예약과 증거의 정확한 해시를 유지하는 용도로만 남아 있습니다.
컨트롤러 런타임은 지원되는 Node 24 도구 모음을 사용합니다.

`recipe.js`는 결정적인 버전/해시, 관리형 CI 및
`.system-bootstrapper/build-v1/` 아래의 파일을 반환합니다.
관리형 Dockerfile은 전용 컨텍스트 제외 파일로 Git 메타데이터, dotenv 재정의 및 비공개 자료를 제외합니다.
현대 프로필 검사는 린트, Vitest, TypeScript/Vite 빌드 및 설정 내보내기를 실행합니다.
레거시 프로필은 소스 가져오기 도구에서 안전성이 확인된 사전 검사 설정만 CRA에 제공하고,
Jest에는 `CI=true`를 설정합니다.
독립적인 브라우저 검사는 렌더링된 UI, 프로젝트 탭 및 중첩 SPA 경로를 검증하고 외부 자원을 차단하며 증거를 저장합니다.

각 CI 작업은 고유 이름과 고정 다이제스트의 BuildKit 빌더를 만들고,
종료 시 해당 빌더/캐시와 자체 이미지 참조를 제거합니다.
후보 컨테이너와 내부 네트워크는 별도로 이름을 붙이고 제거합니다.
전역 Docker 정리, 데몬 다시 시작 또는 플랫폼 서비스 변경은 이 검사의 일부가 아닙니다.
강제 종료 시 소유 자원이 남을 수 있습니다.
대상 복구 전에 정확한 작업 이름을 확인하고 무관한 플랫폼 자원을 정리하지 마세요.

## 활성화 및 복구

Sync 모듈은 미리보기, 활성화 및 상태 함수를 제공합니다.
서버는 소스 가져오기 실행 기록을 보존하고 별도의 버전 1 `build` 객체를 저장합니다.
정확히 미리 본 레시피 해시, 완료된 관리형 소스 등록 및 설정된 로컬 레지스트리가 필요합니다.
임시 GitLab API 인증 정보는 기존 Rails 어댑터 내부에 머무르며 외부 ensure에서 취소합니다.

어댑터는 저장소 소유권, 소스 표식, 기본 브랜치 및 예상된 비활성 기본 틀을 확인합니다.
레시피 설치는 보호된 `[skip ci]` 커밋 하나입니다.
이미 있거나 수정된 파일을 거부하며, 중단 후 재시도할 때도
파이프라인을 시작하기 전에 설치 커밋의 부모를 확인합니다.

초기 파이프라인 생성은 세션 범위 PostgreSQL 권고 잠금과
`SYSTEM_WIZARD_PIPELINE_<operation>`이라는 영구 비밀이 아닌 프로젝트 변수를 사용합니다.
변수 범위는 `*`이며 작업과 활성화 커밋을 포함합니다.
무관한 프로젝트 변수는 변경하지 않습니다. 파이프라인 요청을 보내기 전에 의도를 기록합니다.
응답이 불확실하거나 의도 기록 후 프로세스가 중단되면 재시도 시 조회만 허용합니다.
확인 없는 두 번째 파이프라인 POST는 보내지 않습니다.

원래 파이프라인이 나중에 나타나면 새로고침으로 식별 정보를 복구합니다.
나타나지 않으면 실행 기록은 `requires-reconciliation`을 보고합니다.
여기에는 의도를 기록한 뒤 POST를 보내기 전의 의도적인 중단 구간도 포함됩니다.
관리자는 명시적인 복구 전에 기록된 작업, 저장소 및 파이프라인 이력을 확인해야 합니다.
새로고침에서 파이프라인이 없다고 체크포인트를 삭제/초기화하지 마세요.
외부 결과가 불확실할 때 중복 방지를 보장하기 위해 자동 재시도는 의도적으로 제한됩니다.

상태 새로고침은 파일을 설치하거나 파이프라인을 생성하지 않습니다.
기록된 파이프라인 SHA/참조/소스와 두 개의 선택 사항이 아닌 필수 작업이 성공하고,
아티팩트의 소스 커밋, 파이프라인 식별 정보 및 설정된 레지스트리의 정확한 SHA-256 다이제스트가
일치한 후에만 후보를 검증합니다. 브라우저 및 빌드 검사 증거가 있어야 합니다.
검증에 실패하면 조사할 작업/파이프라인 식별 정보는 유지하면서 오래된 검증 아티팩트 주장을 제거합니다.

## 검증 조건

픽스처는 `tests/gitlab/wizard-build.rb`, `tests/wizard/build-recipe.js` 및
`tests/wizard/build-workflow.js`이며 공유 테스트 매니페스트가 격리 검사를 선택합니다.
새 잠금 파일 설치, 실제 선택한 도구 모음 검사, 후보 HTTP/브라우저 검사 및
실제 GitLab/Runner/레지스트리 실행은 별도의 통합 검증 조건입니다.
캐시된 빌드 의존성과 픽스처만으로 전체 절차를 입증할 수 없습니다.
일치하는 소스/파이프라인/이미지 증거를 비공개로 보관하고 후보를 승격하기 전에 네이티브 작업 정리를 검증하세요.

## 지원되는 Wizard 도구 모음 프로필

레거시 `build-v1` 레시피는 기록된 해시와 과거 GitLab 증거를 위해 바이트 단위로 유지됩니다.
검증된 스냅샷이 Vite를 사용하는 새 소스 가져오기는 Node 24 / Vite 8 계열을 선택합니다.
새 예약은 `node24-vite8-quickstart-v5`를 사용하며
Node 24.22.0/npm 11.19.1, 잠금 파일 설치, 린트, Vitest,
TypeScript/Vite 빌드 및 Playwright 1.64.1 브라우저 검사를 수행합니다.
두 프로필은 동일한 범위 제한 작업 이름과 아티팩트/다이제스트 계약을 사용합니다.
현대 아티팩트는 Jest 실행을 주장하는 대신
`unitTests`, `testRunner: vitest`, `lint` 및 `typecheck`를 보고합니다.

예약된 빌드는 항상 정확히 알려진 레시피 해시를 선택하며 알 수 없는 해시는 거부합니다.
Review/Beta 예약은 일치하는 빌드 레시피 해시를 유지하고,
변경 불가능한 도우미는 기준 빌드 예약과 여전히 일치하는지 확인합니다.
따라서 현대 프로필은 이전 GitLab 레시피를 다시 작성하거나 현재 배포 체크포인트를 자동 무효화하지 않습니다.
기존 가져온 프로젝트의 소스/도구 모음 제자리 업그레이드에는 별도로 검토한 마이그레이션이 필요합니다.
새 스냅샷 가져오기는 지원되는 프로필을 직접 사용할 수 있습니다.

## 정확한 기본 태그 정리

기록된 `legacy`와 `node24-vite8` 레시피는 기존 실행 기록과 과거 증명을 위해
바이트 단위로 유지됩니다. 이 레시피에는 알려진 정리 제한이 있습니다.
태그가 없는 브라우저 이미지는 Docker에 `:latest`로 기록되어
과거의 정리 비교가 성공을 보고하면서도 작업 태그를 남길 수 있습니다.

현재 예약되지 않은 빌드는 `legacy-ca-v4` 또는 `node24-vite8-quickstart-v5`를 사용합니다.
버전별 cleanup-v2 프로필의 수정된 정리 구현을 상속하며,
현대 프로필은 아래의 이동 검사도 상속합니다.
정리 로직은 마지막 저장소 경로 요소에 태그가 없을 때만 `:latest`를 추가합니다.
레지스트리 포트는 보존하고 명시적 태그와 다이제스트 참조는 변경하지 않습니다.
삭제는 정리나 강제 이미지 제거 없이 정확한 해당 태그/참조만 대상으로 합니다.
서로 다른 레시피 해시가 변경을 명시합니다.

이 컨트롤러를 설치해도 기존 기준 빌드나 실행 기록은 다시 작성되지 않습니다.
이미 예약된 레시피는 정확한 과거 해시를 계속 선택합니다.
이전 프로필과 수정된 프로필을 모두 인식하는 일치하는 컨트롤러/도우미를 사용하세요.
보호된 [빌드/환경 전용 마이그레이션](../wizard-upgrade/README.md#build-and-environment-recipes-without-reimporting-source)으로
활성 기준 프로젝트를 수정된 프로필로 옮기고 네이티브 작업 정리를 검증하세요.
마이그레이션은 현재 소스 수정 내용, 소스 가져오기 표식, 중지된 환경 하한 및 무관한 설정을 유지해야 합니다.
전체 소스 가져오기 마이그레이션을 정리 전용 변경의 지름길로 사용하면 안 됩니다.

## 개요 이동 호환성

`node24-vite8-overview-v3` 프로필은 정확한 현대 cleanup-v2 도구 모음,
CI, 필수 작업 이름 및 아티팩트 계약을 유지합니다.
브라우저 스크립트만 변경됩니다. 최상위 **개요** / **Wizard** 탭이 있으면
초기 **시작하기** 제목과 선택된 개요 탭을 확인하고 Wizard를 연 뒤
연결, 프로젝트, 설정 ZIP/Cube 검증 및 중첩 SPA 대체 경로를 검사합니다.
개요로 갔다가 돌아와도 선택한 프로젝트 탭이 유지되는지,
**Wizard 열기** 작업이 작동하는지 검증합니다.
개요와 작업 공간 스크린샷을 보관합니다.
이 탭이 없는 이전 현대 소스는 작업 공간으로 바로 들어가는 브라우저 경로를 유지합니다.

cleanup-v2 두 프로필을 포함한 이전 프로필은 정확한 예약 해시로 계속 선택할 수 있습니다.
새 컨트롤러는 설치된 레시피를 교체하거나 실행 기록을 다시 작성하지 않습니다.
기본 개요를 추가하는 소스를 배포하기 전에 명시적인 `buildProfile`에
`node24-vite8-overview-v3` 또는 `node24-vite8-ca-v4`를 지정하고
일치하는 변경 불가능한 도우미로 보호된 빌드/환경 전용 마이그레이션을 수행하세요.
나중의 연결 또는 재시도를 위해 선택한 프로필을 비공개 운영자 옵션에 유지하세요.
운영 환경 승격은 별도의 의도적인 작업입니다.

## 검토된 공개 CA 신뢰

`legacy-ca-v4` 및 `node24-vite8-ca-v4` 레시피는 저장소에서 검토한
공개 Mozilla CA 번들과 체크섬 검증 갱신 스크립트를 관리형 파일에 추가합니다.
빌드 및 브라우저 이미지는 번들을 오프라인으로 설치하고 Node는 OpenSSL CA 신뢰를 사용하므로
내장된 과거 CA 목록이 제거된 신뢰를 다시 도입하지 않습니다.
현대 프로필은 생성된 레시피에 기록된 검토된 Node 기본 이미지도 사용합니다.
버전과 레시피 해시가 이 변경을 정확한 입력값에 연결합니다.

기존 예약은 원래 바이트와 증거를 유지합니다.
이미 관리되는 프로젝트는 명시적인 `buildProfile`에 `node24-vite8-ca-v4`를 지정하고
승인된 변경 불가능한 도우미를 사용하여 보호된 빌드/환경 전용 마이그레이션으로 업그레이드한 뒤
작업 이미지를 다시 빌드하고 테스트하세요.
컨트롤러만 교체해도 예약된 프로젝트 레시피는 갱신되지 않습니다.
이 갱신은 생성된 이미지와 CI 작업을 위한 것이며 호스트 신뢰 저장소 유지보수 명령이 아닙니다.
배포별 사용자 정의 CA는 별도로 검토하세요.

## 빠른 설치 및 통합 문서

`node24-vite8-quickstart-v5` 프로필은 정확한 CA-v4 도구 모음,
CI 검증, 정리 및 공개 신뢰 파일을 상속합니다.
브라우저 스크립트만 현재 인터페이스에 맞게 변경합니다.
**작동 방식**, 개요 카드 세 개, **System Bootstrapper 설치**의 스크롤/포커스 동작,
정확한 **빠른 설치** 명령 및 통합 안내서 이동을 검사합니다.
개요/문서/Wizard 간 프로젝트 선택을 유지하고 설정 ZIP과 정확한 Cube를 검증하며,
중첩 SPA 대체 경로와 직접 `/configuration` 진입을 모두 확인합니다.
개요, 문서 및 Wizard 스크린샷은 브라우저 증거로 계속 제공됩니다.

이 프로필에는 현재 소스 UI가 필요하며 과거 예약 레시피를 재해석하지 않습니다.
관리형 파일을 해당 소스와 함께 배포한 뒤 적절한 관리형 가져오기 또는 소스 기준 절차에서
`"buildProfile": "node24-vite8-quickstart-v5"`를 명시적으로 연결하세요.
보호된 업그레이드는 이 프로필에서 더 오래된 브라우저 검사로의 다운그레이드를 거부합니다.

격리된 로컬 빌드에 정확한 스모크 스크립트를 실행하려면
`WIZARD_BASE_URL`에 HTTP 원본을, `WIZARD_EVIDENCE_DIR`에 비공개 출력 디렉터리를 설정하세요.
관리형 컨테이너 기본값은 `http://wizard-candidate`와 `/evidence`이며,
선택한 원본 밖의 모든 요청은 차단됩니다.
