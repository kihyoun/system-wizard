# 시스템 진단

연결된 Wizard에서 **시스템 진단**을 여세요. 대화 상자를 열면 구성된 대상과
사용 가능한 관리형 Runner 이름을 읽습니다. 네트워크 검사나 이미지 가져오기는 수행하지
않습니다. 동작에는 인증된 Sync 연결이 필요하며 CI를 시작하지 않아도 사용할 수 있습니다.
기존 유지 관리 잠금이 동작을 일시적으로 차단할 수 있습니다. 검사는 파이프라인을 만들거나,
구성을 바꾸거나, 서비스를 다시 시작하거나, 캐시를 정리하거나, 이미지를 삭제하지 않습니다.

## 레지스트리 연결 확인하기

구성된 GitLab 레지스트리 또는 구성된 도우미 이미지 레지스트리를 선택하고
**연결 검사**를 누르세요. 대상은 저장된 서버 구성에서 가져오며 임의의 브라우저
URL에서 가져오지 않습니다. 스킴과 명시적 포트는 유지됩니다. 명시적 포트가 없는 HTTP
GitLab 레지스트리의 경우 생성된 GitLab 리스너는 포트 5050을 사용합니다. 도우미
레지스트리가 같은 레지스트리이면 구성된 GitLab 스킴을 사용하고, 다르면 컨트롤러 검사는
HTTPS를 사용합니다. 데몬에는 별도의 insecure-registry 설정이 있을 수 있으며 이 검사는
그 설정을 추정하지 않습니다.

결과는 **Sync 컨트롤러 프로세스 네트워크**를 식별합니다. DNS는 서버의 리졸버와 hosts
파일을 사용합니다. 후속 단계는 처음 해석된 주소를 검사하며 HTTP와 TLS에는 원래
호스트 이름을 유지합니다. 다른 주소는 검사하지 않습니다. 이 관찰 결과는 브라우저,
Runner 컨테이너, CI 작업 또는 Docker 데몬에서의 연결성을 입증하지 않습니다.
구성된 비공개 레지스트리 주소도 지원합니다. 사설 주소를 일괄 금지하면 일반적인
로컬 설치를 사용할 수 없게 됩니다.

| 검사 | 성공 결과가 입증하는 사항 | 한계 |
| --- | --- | --- |
| DNS | 컨트롤러의 리졸버가 주소를 반환했습니다. | 다른 네트워크에서는 다르게 해석할 수 있습니다. |
| TCP | 해당 주소와 구성된 포트에 연결이 도달했습니다. | 시간 초과만으로 차단이나 이미지 누락을 입증할 수 없습니다. |
| TLS | 인증서 체인과 호스트 이름이 컨트롤러의 신뢰 검사를 통과합니다. | Docker의 신뢰 구성이 다를 수 있습니다. HTTP 대상은 TLS를 건너뜁니다. |
| 레지스트리 HTTP | 엔드포인트가 `/v2/`에서 예상한 레지스트리 응답을 반환했습니다. | 자격 증명, 권한 및 이미지 존재 여부는 확인되지 않습니다. |

한 단계가 실패하면 종속 단계는 소요 시간 0으로 **검사하지 않음**으로 표시됩니다.
소요 시간은 관찰된 단계를 설명합니다. 예상된 HTTP 401 인증 요구 응답은 도달 가능성
검사 성공을 뜻하지만 Runner를 인증하지는 않습니다. 200 응답도 레지스트리 API임을
식별해야 합니다. 리디렉션과 인식되는 인증 요구가 없는 401을 포함한 다른 HTTP 상태는
별도의 응답 사실로 표시됩니다. 리디렉션은 따라가지 않습니다. 본문, 인증 요구 내용,
토큰, 인증서 키 및 가공하지 않은 서버 오류는 반환하지 않습니다.

## 정확한 도우미 이미지 가져오기 시도하기

**도우미 이미지 다운로드 시도**는 별도 동작입니다. 먼저 실행 중인 관리형 Runner 관리자를
선택하세요. 대화 상자는 실행 전에 정확한 불변 도우미 이미지 참조를 보여 줍니다.
기본값은 `gitlab/security-release.json`에서 가져옵니다. 운영자는 서버 구성에서
`GITLAB_RUNNER_HELPER_IMAGE`를 설정할 수 있습니다. 이미지에는 명시적인 SHA-256
다이제스트가 유지되어야 합니다. 클라이언트는 다른 이미지나 Docker 엔드포인트를 제출할 수 없습니다.

Sync는 선택한 관리자와 등록을 검사합니다. 지원되는 관리형 Runner 풀은 호스트 소켓
`/var/run/docker.sock`을 바인딩합니다. Sync는 실제 호스트 데몬에 가져오기를 요청하기
전에 해당 바인딩과 Runner Docker 호스트 설정을 확인합니다. 또한 Docker 등록이
정확히 하나이고 도우미 이미지 참조가 구성된 이미지와 일치해야 합니다. 중지된 관리자,
변경된 도우미 참조, 원격 Docker 엔드포인트, 모호한 구성 또는 지원하지 않는 Docker
자격 증명/호스트 환경은 안전하게 거부됩니다. 운영자가 해당 구성을 검토해야 합니다.
이 기능은 다른 Runner 데몬 대신 컨트롤러 데몬을 조용히 대입하지 않습니다.

도우미 이미지 가져오기는 익명이며 Runner별 자격 증명을 검사하지 않습니다. 자격 증명
재정의는 운영자가 별도로 검증해야 합니다. 성공은 해당 데몬이 정확히 이 도우미 이미지
가져오기를 완료했음을 확인합니다. CI 시작, 작업 네트워크, 다른 레지스트리 인증 또는
다른 이미지의 가용성은 입증하지 않습니다. 컨트롤러 HTTP 검사 성공과 데몬 가져오기
실패는 둘 다 정확할 수 있습니다. 가져오기 오류는 가공하지 않은 데몬 출력 대신 고정된
안전한 레이블로 표시됩니다. 이 결과만으로 IP 차단, 자격 증명 오류 또는 다이제스트
사용 불가를 입증하지는 않습니다.

**가져오기는 레이어를 다운로드하고 선택한 데몬의 디스크/캐시 공간을 사용할 수 있습니다.**
기존 레이어를 재사용할 수 있습니다. 아무것도 정리하거나 삭제하지 않습니다. 요청 시간이
초과되거나 출력 제한을 넘으면 데몬은 작업을 계속하고 부분적으로 다운로드한 레이어를
보관할 수 있습니다. 다시 시도하기 전에 데몬 상태를 확인하세요.

## 제한과 재현 가능한 검증

Sync는 대상 검사를 포함하여 최대 두 개의 동시 진단 요청과 한 번에 하나의 가져오기
요청을 허용합니다. DNS, TCP, TLS 및 HTTP 각 단계의 제한 시간은 3초입니다.
Docker 메타데이터 읽기는 제한 시간 3초와 출력 제한 256 KiB를 사용합니다. 가져오기
관찰은 45초 또는 출력 1 MiB에서 중단하며, 개별 스트림 레코드는 64 KiB로 제한됩니다.
HTTP 응답 헤더는 16 KiB로 제한하고 본문은 버립니다. 사용 가능한 관리자 이름은 최대
100개를 반환합니다. 진단 결과는 디스크에 저장되거나 Sync에 보존되지 않습니다.
응답은 `Cache-Control: no-store`를 사용하며 Wizard는 대화 상자를 닫을 때까지 현재
결과만 유지합니다. 요청 제한은 관찰의 범위를 제한하며, 클라이언트 연결 해제 후에도
계속되는 데몬 작업을 제한하지는 않습니다.

문서화된 Node 런타임과 Sync 의존성을 설치한 체크아웃에서 제어된 픽스처 테스트를 실행하세요.

```sh
npm --prefix sync run build
node --test tests/sync/system-diagnostics.js
```

테스트는 인증, 허용 대상, 순서대로 발생하는 실패, 건너뛴 단계, 레지스트리 인증 요구,
HTTP 리디렉션, Runner의 소켓과 이미지 식별 정보, 구성 변경, 민감 정보 제거, 동시성,
출력 제한 및 시간 초과를 검사합니다. HTTP 연결 성공 후 데몬 가져오기가 실패하는 경우도
포함합니다. 픽스처는 로컬 리스너와 격리된 가상 Docker 소켓을 사용합니다. 실제 이미지
가져오기나 실행 중인 플랫폼은 필요하지 않습니다.
