# Seed와 설정 함께 백업하기

인증된 Wizard에서 **통합 백업**을 선택한 다음 **Seed 및 설정 백업**을 직접
시작하세요. 이 작업은 서비스를 중지하기 전에 기본 Harvest 진입점을 통해
선택한 백업 파일시스템, 마운트 식별 정보와 여유 공간을 확인합니다. 매체가
없거나 올바르지 않으면 오류로 처리하며, 시스템 디스크에 대체 백업 디렉터리를
만들지 않습니다. 평상시 서비스는 별도로 선택한 운영 저장소를 계속 사용합니다.

## 두 가지 복구 입력

완료된 Seed는 선택한 외부 매체의 `SEED_DIR/snapshots/<generation>` 아래에
남습니다. `current` 링크는 가장 최근에 완료된 스냅샷을 가리킵니다. Wizard는
일반적인 `bootstrapper.zip` 설정 백업을 별도의 인증된 다운로드로 제공합니다.
이 파일에는 설정과 비밀 값이 들어 있으므로 안전하게 보관하고, 백업 대상
서버와 별개인 곳에 저장하세요. 서버에 남는 임시 사본은 다운로드 재시도를
위한 것이며, 유일한 사본으로 의존해서는 안 됩니다. 서버는 운영자가 해당
파일을 명시적으로 삭제할 때까지 비공개 설정 상태 디렉터리에 완료된 다운로드
파일을 보관합니다. 공간을 확보하려고 진행 중인 작업이나 그 작업의 잠금을
삭제하지 마세요.

`bootstrapper.json`과 `recovery.json`에 포함되는 기존 버전 관리 복구 메타데이터는
정확한 Seed 세대, 매니페스트 SHA-256, 기본 작업 완료 시각, GitLab 이미지 식별
정보, 설정 캡처 시각과 캡처한 각 ENV 파일의 SHA-256을 기록합니다. 복구 전에
이를 보관한 Seed 매니페스트 및 ZIP 항목과 비교하세요. ZIP 다운로드 자체의
SHA-256도 화면에 표시됩니다. 설정의 비밀 값이나 설정 내용은 Seed 매니페스트에
추가되지 않습니다.

## 진행 상황과 실패

전역 저장소 잠금과 설정 도우미 잠금은 캡처, Harvest, 내보내기가 진행되는 동안
동시에 설정을 변경하지 못하게 합니다. 인증서 잠금도 캡처와 Harvest 전체에
걸쳐 유지됩니다. ZIP은 기존 Wizard 모델과 ZIP 내보내기 도구를 재사용하며,
캡처한 기본 및 프로젝트 ENV의 바이트를 정확히 보존합니다. 브라우저에서 아직
저장하지 않은 편집 내용은 내보내지 않습니다. 기본 Harvest는 필요한 정지 상태
백업 검증을 계속 수행하며, 작업이 완료되거나 처리 가능한 실패가 발생하면
GitLab을 다시 실행합니다. 파이프라인이나 자동 복구 예행연습은 시작하지 않습니다.

상태를 새로 고쳐 사전 확인, 캡처, Harvest, ZIP 내보내기 진행 상황을 확인하세요.
대화상자를 닫아도 기본 도우미는 취소되지 않습니다. 같은 브라우저 세션에서는
마지막 작업을 다시 열 수 있습니다. 브라우저에서 다운로드한 뒤 ZIP을 안전하게
저장했는지 확인하세요. 다운로드를 시작했다는 사실만으로 브라우저가 실제로
저장했음을 증명할 수는 없습니다. 서로 독립적인 두 복구 입력을 모두 보관해야
백업 쌍이 완성됩니다.

Harvest가 실패하면 이전에 완료된 Seed를 보존합니다. 새 Seed는 완료되었지만
내보내기가 실패한 경우에는 부분 완료로 표시하고 새 세대를 알려 줍니다.
이때 이전 ZIP이 새 Seed와 일치한다고 표시하지 않습니다. 오류를 해결한 뒤
작업을 반복하세요. 브라우저 다운로드가 실패하면 보관된 ZIP을 다시 다운로드할
수 있습니다. 도우미 완료나 서비스 재개 여부가 확실하지 않으면 재시도 전에
기본 작업과 남아 있는 잠금을 확인하세요. 사용 중인 잠금을 제거하거나,
준비 디렉터리를 완료된 상태로 승격하거나, 확인되지 않은 작업을 완료되었다고
취급해서는 안 됩니다.

기본 도우미가 완료되고 GitLab이 다시 실행된 뒤에만 백업 매체를 분리하세요.
중단되었거나 완료 여부가 불확실한 작업은 먼저 점검해야 합니다. 과거 스냅샷은
보존하며, 보존 정책과 삭제는 계속 명시적인 작업으로 수행합니다.

## 호환성과 복구

일반 설정 열기, 백업, 전송, 가져오기와 개별 Harvest 및 복구는 기존 동작을
유지합니다. 백업 쌍 메타데이터가 없는 이전 백업도 기존 수동 대응 절차로 사용할
수 있습니다. 백업 쌍의 JSON을 열면 과거 메타데이터를 검증되지 않은 근거로
유지하고 Seed 일치 주장은 해제합니다. 이를 편집하거나 다시 내보내더라도
새로운 백업 쌍이 되는 것은 아닙니다.

일치하는 완료 Seed, 설정 ZIP, 호환되는 복구 도구와 새로 가져온 소스를 사용해
[복구 규약](RECOVERY_CONTRACT.md)을 따르세요. 일치하는 체크섬은 대응 관계와
무결성을 확인하지만, 자동 복구를 허가하거나 이미지 본문을 별도로 확보했음을
증명하지는 않습니다.
